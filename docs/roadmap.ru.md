# Roadmap и открытые вопросы

[English](roadmap.md) · Русский

Порядок по тому, как часто ограничение будет мешать на практике. Пункты остаются в границах проекта:
поведение самого Hibernate и две автоматические единицы работы (транзакция, servlet-запрос);
всё остальное оборачивается из тестового кода через `detector.inScope(...)`.

1. **Проверить заявление об отсутствии ложных срабатываний на реальных наборах.** Прогнать стартер
   с `nplusone.fail-test=false` на нескольких существующих наборах интеграционных тестов и посчитать,
   сколько неявных нарушений оказались реальными N+1, а сколько сознательными повторами. Порог по
   умолчанию и граница между падением и логированием держатся на этом соотношении.
2. **Переопределение на уровне теста.** `@NPlusOneGuard(maxRepeats = 5)` или
   `@NPlusOneGuard(enabled = false)` на тестовом методе или классе для редкого сознательного повтора,
   которому не место в глобальном allowlist.
3. **Опциональный отчёт JPlusOne при падении.** Если `com.adgadev.jplusone` есть в classpath, добавлять
   в сообщение об ошибке дерево вызовов сессии (`nplusone.report=true`).
4. **Место вызова для явных повторов.** Захватывать первый фрейм приложения, выполнивший повторный
   явный запрос, чтобы подсказка называла цикл, а не только SQL.
5. **Публикация в Maven Central** после проверки на реальных наборах тестов.
